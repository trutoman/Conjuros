## Why

Conjuros stores strongly related, owner-scoped data (users, items, tags, tag categories, themes), but MongoDB gives no schema, no referential integrity and no versioned migrations: uniqueness, ownership and "kind determines fields" rules live only in application code, and legacy-shape hydration plus one-shot migration scripts keep accumulating. PostgreSQL with Drizzle ORM provides a typed, versioned schema, database-enforced integrity and transactional multi-row writes (reorder, tag cascades). The new database starts from scratch, so no data migration is required.

## What Changes

- **BREAKING**: PostgreSQL replaces MongoDB as the only datastore. Existing MongoDB data is **not** migrated: the new database starts empty (default themes are seeded on first start and users register again). The `backup-*/` dump is left untouched and is no longer read by anything.
- Add `drizzle-orm` and `pg` (runtime) and `drizzle-kit` (dev). The schema is declared in code (`src/api/db/schema.ts`), SQL migrations are generated by `drizzle-kit` and committed under `drizzle/`, and the API applies pending migrations at startup. New scripts: `db:generate`, `db:migrate`.
- Replace every `Mongo*Repository` with a Drizzle/PostgreSQL implementation behind the **same repository interfaces**. In-memory repositories, services, controllers, routes and the frontend are unchanged.
- Keep Zod as the single source of API validation, still in `@conjuros/contracts` and unchanged. `drizzle-zod` is **not** adopted (see design.md): v0.8 emits Zod 4 (`zod/v4`) schemas while the contracts use the Zod 3 API, and generated schemas cannot express the contract rules or hide persistence-only fields such as `ownerId`. Database enum values are derived from the contract constants so they cannot drift.
- Configuration: `MONGODB_URI` and `MONGODB_DATABASE` are replaced by one validated `DATABASE_URL` (`postgres:`/`postgresql:`). Compose adds `POSTGRES_USER`, `POSTGRES_PASSWORD` (required) and `POSTGRES_DB`.
- Compose: the `db` service becomes a pinned PostgreSQL image with a named `postgres_data` volume, a `pg_isready` healthcheck and host port `127.0.0.1:5432`; the `api` service receives a `DATABASE_URL` that targets `db`.
- Tests: repository behavior is verified against an in-process PostgreSQL (PGlite) with the committed migrations applied, so `npm run check` stays Docker-independent; the Docker persistence test is ported to PostgreSQL.
- Remove Mongo-only code: the `mongodb` dependency, `scripts/backfill-content-null.mjs`, `scripts/migrate-tag-category-storage.*`, `scripts/normalize-tag-categories.mjs`, the migration script test and the `migrate:backfill-content` script.
- Update `README.md`, `AGENTS.md`, `.env.example` and the persistence references in `docs/init.md`.

## Capabilities

### New Capabilities
- `postgres-persistence`: PostgreSQL accessed through Drizzle ORM is the system of record; covers `DATABASE_URL` configuration, versioned migrations applied at startup, the from-scratch (no data migration) start, database-enforced integrity, preserved query semantics, atomic reorder and tag cascades, and Docker-independent repository verification.

### Modified Capabilities
- `container-stack`: the `db` service is PostgreSQL and the API reaches it over the stack network through `DATABASE_URL`, instead of MongoDB at `mongodb://db:27017`.
- `developer-environment`: local setup, `.env` requirements, ports (`5432`), database-only start and the Docker persistence test target PostgreSQL; adds the generated-migration workflow for schema changes.
- `tag-category-migration`: every requirement is removed because the one-shot MongoDB migration script no longer exists.
- `tag-category`: the `general` category is no longer created "on migration".
- `tag-management`: migration and legacy-document language is removed from the "Existing tags use normalized lowercase categories" requirement; runtime read normalization is kept.

## Impact

- **Dependencies**: add `drizzle-orm`, `pg`, `drizzle-kit`, `@types/pg`, `@electric-sql/pglite`; remove `mongodb`; `pnpm-lock.yaml` changes.
- **API code**: new `src/api/db/` (schema, client, migration runner); the five `src/api/repositories/*.repository.ts` files gain Postgres implementations and lose the Mongo ones; `connection.ts` is removed; `src/api/server.ts` wiring and `src/api/config/environment.ts` change (`databaseUrl` replaces `mongoUri`/`databaseName`).
- **Root files**: new `drizzle.config.ts` and `drizzle/` migrations; `tsconfig.json` includes the config file; `Dockerfile.api` copies `drizzle/`; `docker-compose.yml`, `.env.example`, `package.json` scripts updated.
- **Tests**: `environment.test.ts`, `docker-availability.test.ts` and `docker-compose.test.ts` updated; the migration script test is deleted; new repository tests run on PGlite.
- **Docs and specs**: `README.md`, `AGENTS.md`, `docs/init.md`; delta specs listed above.
- **Local setup**: contributors must update their `.env` (`DATABASE_URL`, `POSTGRES_PASSWORD`) and recreate the database container; the old `mongo_data` volume can be deleted manually and is never touched by this change.
